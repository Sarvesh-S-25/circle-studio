# Codex acceptance evidence — 22 October 2026

Installed CLI: **codex-cli 0.163.0**. Generated app-server JSON schemas were inspected locally. They accept `untrusted`;
Circle retains that policy on start/resume/fork and discloses engine-dependent approval coverage.

The human approved a real-account probe using the existing ChatGPT CLI sign-in. All model work used newly created
temporary fixture folders, not registered projects or Circle's real data. `scripts/codex-smoke.mjs --real` ran four
small turns; a separate `--edit-only` probe corrected the requested write method without weakening the policy.
Detailed local evidence is under ignored `tests/e2e/shots/codex-live-smoke.json` and `codex-live-edit.json`.

| Scenario | Observed result |
|---|---|
| Read/command approval | Read commands raised command requests; the fixture handler allowed normal requests. |
| Initial shell write | Circle's dangerous-command policy refused it. The model reported the refusal; no result file was created. This was not a successful edit. |
| Native file change | Explicit native `apply_patch` produced an Edit request with the exact fixture path; allowed. `result.txt` contained exactly `CIRCLE_RESULT_OK`. A subsequent approved command read it back. |
| Resume and denial | Same thread ID resumed; a denied attempt to write `denied.txt` stopped without creating the file or retrying another route. |
| Outside-folder read | A read of an expressly owned sibling fixture raised a request classified outside-project; denied. Model reported denial. No other outside access was requested. |
| Interrupt | Resumed read-only turn interrupted after session initialization; adapter returned `stopped`. |
| Model discovery | Read-only RPC returned seven models. No model turn was started by this query. |
| Project history | Read-only list returned the newly created thread in its project. Paged turns returned its user/assistant messages. |
| Effective MCP configuration | `config/read` for the fixture returned one configured connection. Only names/status metadata was retained; no raw configuration/credentials were returned. |
| Account limits | Account/rate-limit queries succeeded with an available account reading. No raw identity or sign-in credential was recorded. |

This evidence does **not** establish universal interception, live question-category coverage, independent terminal control,
forking, or every future CLI version. The adapter's default `liveVerified` remains false until engine detection matches
the recorded version; the engine listing exposes the scoped scenarios. Model self-reports are not approval evidence:
request events and actual fixture files determine the observations above.
